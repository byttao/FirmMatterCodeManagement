# v0.6.3 导出与备份恢复

## 导出
项目列表按当前年度、筛选及可见列提交；看板和签字人页也转入导出任务页。POST /api/export-jobs 需 Idempotency-Key，返回202；同键同内容重试复用任务，不同内容409。GET任务列表/详情、POST取消、GET认证下载；原同步导出接口已删除。

每实例同时生成1项，全局最多20项未完成、每人最多2项；默认500行一批、5万行、5分钟、50MiB、可用磁盘至少100MiB、WAL上限256MiB。超过预算失败并要求缩小范围，绝不截断冒充完整。导出说明记录筛选及同一SQLite读取快照时间，项目按数据库id顺序输出。权限在提交、开始、批间、下载重新核对；身份/项目关系变更保守使旧任务失效。

关闭页面不取消任务；排队立即取消、运行按批取消。主服务监管独立worker，文件锁只允许一个进程；重启后遗留running失败，queued继续核权。文件先写私有partial再原子转ready；成功后24小时过期，任务元信息30天。默认导出不含银行全号；敏感批量导出需要单独权限、用途、确认和审计。

下载全实例同时1个、100KiB/s，其他请求429并返回Retry-After；读取期间不持数据库写锁，不支持Range。页面显示大小/有效期/预计下载时间。已交付浏览器的副本不能远程撤回。只读租约允许原本获权人员导出，不增加权限。

管理员可通过服务环境调整 FIRM_EXPORT_MAX_PENDING、FIRM_EXPORT_MAX_ROWS、FIRM_EXPORT_MAX_SECONDS、FIRM_EXPORT_MAX_BYTES、FIRM_EXPORT_DOWNLOAD_KIB。限額必须根据目标主机实测调整；此限速不是云平台QoS。

## 加密备份
管理员“备份与恢复”页输入12–128位密码并二次确认，下载.ymhb。备份采用SQLite backup API一致性快照，包含业务数据库、billing.key、device-identity.json，以及存在的license-state.json/server.json/manager-settings.json；不含临时导出文件。Scrypt派生密钥＋AES-GCM认证，清单逐文件SHA256。总原始内容/加密文件上限200MiB，生成预算120秒，单任务生成与传输限制。密码单独保管，不能从文件找回。

请把加密文件复制到本机之外的受控存储，定期在隔离空目录演练。不要在服务运行时仅复制db.sqlite，不要使用实时网盘/NAS作为服务数据目录。

## 同版本灾难恢复
1. 保留原安装目录及故障数据，不覆盖。停止服务，准备同版本完整ZIP，在新的本地目录解压；保持原发行公钥。
2. 在命令行运行：`BackendServer.exe --restore-backup "备份.ymhb" "C:\\FirmRestored\\data"`。目标data须全新/空，密码交互输入，不写命令历史。不要先初始化新管理员。
3. 恢复检查产品/结构600、文件清单、SQLite完整性/外键、设备公钥标识、开票版本和发票快照AES认证；旧会话全部撤销，不生成替代密钥。
4. 在新目录配置服务和目录ACL，启动对应程序，用恢复账号重新登录。恢复库进入写入保护，导出文件失效需重新生成。
5. 管理员“备份与恢复”逐规则填写外部实际已交付最大序号（不得小于备份值），记录依据并确认。审计成功后解除保护。核号只防编号重用，不能补回备份后丢失的项目/财务记录，需根据外部档案人工重建。

旧结构迁移、原地升级及许可证兼容不在本轮范围。管理工具提供完整新版下载，旧升级执行入口停用。
