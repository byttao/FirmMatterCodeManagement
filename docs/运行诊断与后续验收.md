# 中文错误、运行诊断与管理员排查验收

本次基线：编号软件v0.6.4、授权中心v0.4.3；业务结构600、中心结构300、设备协议2。未增加旧版兼容或自动清库。两套软件独立部署，不共享数据库。

## 已实现的错误约定

API错误正文为`detail: {code, message, category, request_id}`，响应头提供`X-Request-ID`。401/403归类为登录或权限限制；429为频率/资源限制；一般4xx为操作条件限制；5xx为系统故障。保留明确业务中文原因，英文默认HTTP错误和框架校验不直接转给客户；输入校验按白名单字段名生成中文提示，不回传原输入值。未处理异常返回通用中文提示，不包含SQL、路径、密码或堆栈原文。

网页JSON和二进制下载共用错误格式化；请求编号会显示在提示中。断网/连接失败只能提示客户端记录操作时间、页面和操作，不能伪造服务器请求编号。原生浏览器必填、格式、长度、数值校验改为中文。机器排查代码仍保留英文稳定标识，但不会代替中文原因。第三方浏览器扩展及操作系统自己的提示不属于系统网页控制范围。

## 权限与操作路径

编号软件新增固定权限`diagnostics.read`，只属于office_admin，不能通过special_grants授予其他角色。编号管理员、财务、执业人员、后勤、未登录者均不能读取/导出全局运行日志；页面隐藏与API鉴权同时生效。诊断导出为POST并校验CSRF，不接受用户提交本地路径。停用账号、注销、权限变更后的会话控制沿用原机制。

1. 执业人员保存错误提示中的请求编号、操作时间、页面、操作步骤。不要提供密码、Cookie或客户银行资料。
2. 事务所管理员用自己的账号登录该事务所编号系统，在“运行日志”粘贴请求编号点击查询；必要时按操作用户ID、开始/结束时间、级别缩小范围。
3. 确认用户、时间和失败类别，然后“导出已查询条件的脱敏诊断”。编辑筛选框后要重新查询，导出基于最后一次查询条件，不是尚未提交的输入。
4. ZIP含`logs.jsonl`与`summary.json`，后者列出时间、筛选、条数和truncated。truncated=true时不能断言没有更早错误。
5. 授权中心仍只有一个管理员，不新增角色系统。在其“运行日志”按客户/实例/请求查询，只有签名身份核验成功后才把客户标为已核验。已核验请求同时保留中心HTTP请求编号和编号端协议请求编号，二者任一都可查询。

日志针对当前部署，中心不会读取客户的业务库或自动收集客户所有操作日志。管理员可导出任意本所用户的对应记录，不需要修改执业人员权限，也不需要使用执业人员密码。已删除/轮转日志和未抵达服务器的请求无法凭空恢复。运行诊断不是不可篡改审计证据，业务审计继续由原审计模块承担。

## 日志内容与资源限制

记录UTC时间，页面按Asia/Shanghai显示；带时区的筛选使用真正UTC换算。记录请求编号、已验证用户ID、方法、路由模板、状态码、耗时、源IP、类别、原因码。系统异常只记录类型及最后6个代码帧的文件名/行号/函数名，不序列化异常文本、源码或局部变量。导出任务日志带原请求编号、完整任务ID、提交用户及结果。

默认查询最近24小时，最大范围31天；单次扫描最多12MiB/5000条；最新文件优先、同文件倒序；分页50条，允许最多200条/页。诊断只读白名单日志文件，再按字段白名单投影；不把目录中其他文件打包。单个脱敏日志正文最多5MiB。单进程最多1个扫描、1个诊断生成/下载；下载限速100KiB/s（约0.82Mbps）。日志轮转限制磁盘体积，实际保留期可能早于30天，取决于访问量。达到上限必须提示缩小范围，不把不完整导出宣称为全量日志。

日志写入失败不逆转已经提交的业务操作；进程内丢日志计数可在诊断summary读取，页面显示非零告警。进程重启后计数清零，不代表历史磁盘故障从未发生。5xx只是服务器处理失败的类别，不代表已经查明具体根因。

### R-01（上线前）：目标规格混合负载和资源验收

在真实Windows Server 2019：中心1核2GiB2Mbps，编号端2核4GiB2Mbps。100账号、50独立会话，发号/查询/财务提交/登录/导出/诊断混合运行30–60分钟。保留逐请求样本、P50/P95/P99、CPU/内存、磁盘/WAL、失败率；不能用单线程轮询替代并发。发号不重复、幂等重试不重复记账、越权零泄露是硬要求。建议内网编号P95≤1秒/P99≤3秒作为待实测目标，公网单列带宽/RTT影响；持续内存超过85%、业务5xx或数据库锁等待超时须先分析再扩容。

### R-02（高）：统一所有大文件传输带宽预算

当前业务导出和诊断各有独立限速，备份另有路径；多个下载类型叠加仍可能接近或占满2Mbps。本次只限制新增诊断，不宣称所有传输共享全局预算。修改exports/backups/diagnostics的响应层，使用一个进程级传输协调器或全局令牌桶，给交互请求留余量；禁止用Web进程内大量等待任务占满线程池。验收同时下载业务导出、备份、诊断时总速率受控、取消及时释放槽位、编号和登录仍满足约定延迟。不要改变业务权限或把诊断授权扩大给普通角色。

### R-03（中）：桌面工具的后台请求与取消

license-admin/app/main.py目前同步访问HTTP，超时上限20秒。重构到单个受控工作线程/任务队列，Tk控件只能在主线程after回调更新；提交按钮禁重入；窗口关闭或退出后丢弃过期回调；写操作超时不自动重试，以免重复签发。不要从后台线程调用messagebox或读写Tk变量。以延迟10秒、断网、重复点击、请求中关闭窗口验收：窗口可拖动、操作有进度、无重复写入、无销毁窗口后的异常。保留Cookie/CSRF、代理隔离和不落盘口令规则。

### R-04（中）：运行日志索引与持久化故障告警

当前是有上限文件扫描，繁忙时旧日志可能不在12MiB扫描窗口，truncated有提示但不保证任意历史请求都可快速查到。若现场需要完整30天检索，添加小型只含白名单元数据的索引或按时间切分索引，并记录日志落盘失败的持久化健康状态。为慢磁盘使用有界队列写入，定义队列满时的丢弃计数；不得阻塞已完成发号或无限占用内存。验收百万级记录下查询延迟、断电重启、磁盘满、Windows目录ACL拒写，以及截断提示的正确性。

### R-05（中）：授权变更的一致性与依赖基线

配额/功能及地址更新已有expected_revision；续期、暂停/恢复/撤销等路径仍应统一加入修订检查或幂等语义，覆盖网页和管理工具同时打开旧页面的情况。验收两个窗口交替更改：旧窗口不能覆盖新状态，409中文提示要求刷新。
