# 后勤开票办理任务

业务v0.7.0，结构700，协议2；授权中心仍可使用v0.4.3。此文档对应下一轮批次A。

管理员或财务创建任务，选择未删除项目的已确认启用客户、当前已核验档案版本、启用且具有clerk角色的办理人和本次金额。后勤只看本人任务的项目编号、客户/抬头/税号、本次金额和状态；任务不会授予全客户资料、合同/收款汇总、财务登记、日志或备份权限。财务兼任办理须显式组合clerk角色，专业人数和授权席位规则不变。

入口为“开票办理任务”/“我的开票任务”，与“开票资料核验”分开。后勤在assigned状态点击查看开票资料，经所属关系、启用状态、当前资料及审计校验后读取已有加密版本；列表仅银行末四位，敏感字段不写localStorage。支持单任务复制及HTTP人工复制，只有浏览器确认复制成功才显示“已复制”。撤回、转派或关闭时清空当前敏感展示；已复制内容不能远程收回。

assigned→result_submitted→completed。后勤提交金额/票号/日期仅留下不可变结果，不直接记账。财务确认在同事务创建或关联流水、不可变快照、任务和审计；创建/提交/确认都有Idempotency-Key，修订不匹配409，不能自动替用户覆盖。可显式关联项目、金额、票号、日期、资料版本一致的未作废流水，同一流水只能关联一个任务。

已提交不可直接转派。退回留下原因和原结果历史，当前资料失效时变needs_review；重新核对通过明确revalidate动作指定当前核验版本，不覆盖尚待财务确认的历史结果。客户合并/纠错/停用、项目客户变化/删除、档案停用、新核验版本均重新核查，不能自动更换银行信息。已发生的历史开票允许财务明确勾选历史核对并填写原因后确认，快照保持实际使用版本；普通财务登记仍只接受当前核验版本。

接口：POST/GET /api/billing-tasks；GET /{id}；POST /{id}/reveal、reassign、revoke、submit-result、confirm、return、revalidate；办理人目录GET /assignees仅管理者可用。创建、提交和确认的键在一次明确操作的重试中不变。敏感响应no-store，审计记录actor/task/project/customer/version/request_id及原因，不记录银行全号。

新增billing_tasks、billing_task_results及索引；结果不可变、financial_entry_id唯一。结构600旧库保留原数据，结构700程序明确拒绝不匹配库，本轮不迁移、不清库、不替换密钥。测试和新安装使用新的独立目录；700备份只按同结构恢复。
